## 1. 종합 점수에 들어갔습니다

`전세 여건·투자금 효율 20점`을 이렇게 나눴습니다.

| 항목 | 배점 | 비고 |
|---|---|---|
| 전세가율 | 12 → **10** | 전세 실거래가 없으면 추정치라 배점을 낮춤 |
| **입주 물량** | — → **5** | 신규. 실제로 수집한 데이터 |
| 전세 거래 | 5 → **3** | |
| 필요 투자금 | 3 → **2** | |

총점 100점은 그대로라 기존 점수와 호환됩니다.
항목명은 `전세가율·투자금 효율` → **`전세 여건·투자금 효율`** 로 바꿨습니다.
README 「공통 결과 UI 규칙」에 따라 앱 화면·테스트·검증 스크립트까지 함께 고쳤습니다.

**같은 조건의 단지라도 지역에 따라 점수가 갈립니다.**

| 지역 | 전세 여건 점수 | 입주 물량 항목 | 3년 누적 |
|---|---|---|---|
| 평택시 | **9.6** / 20 | 1.2 / 5 | 27,229세대 |
| 노원구 | **12.0** / 20 | 3.0 / 5 | 2,382세대 |
| 수원영통구 | **14.0** / 20 | 4.5 / 5 | 580세대 |

이 4.4점 차이가 공급만으로 생긴 차이입니다.

## 2. 전국 커버리지를 맞췄습니다

이게 점수 반영의 **선행조건**이었습니다. 수집이 잘 된 지역만 공급 벌점을 받으면
실제 공급 리스크가 아니라 수집 커버리지가 순위를 정하게 됩니다.

| | 이전 (파일 다운로드) | 현재 (오픈API) |
|---|---|---|
| 서울 | 38건 | **192건 · 25개 자치구 전부** |
| 전국 | 서울·경기만 | **2,800건 · 251개 시군구** |
| 총 세대수 | 156,548 | **1,314,749** |
| 갱신 | 수동 | 명령 한 줄 |

전국 전환으로 숫자가 크게 바뀐 곳이 있습니다. 남양주시가 5,686 → **12,082세대**,
평택시가 22,187 → **27,229세대**입니다.

## 3. 유료 리포트 4번 섹션

막대그래프와 함께 자동으로 들어갑니다. **리포트에서 처음으로 그림이 있는 부분입니다.**

> 평택시에 향후 3년간 27,229세대가 입주할 예정입니다. 2027년 상반기에 7,983세대로
> 가장 몰립니다. 이 정도 물량이 들어오면 그 시기 전세는 약세로 가기 쉽습니다.
> 전세를 끼고 매수하실 계획이라면 만기가 2027년 상반기와 겹치지 않도록 잡으시고,
> 실거주라면 그 시기에 오히려 협상 여지가 커질 수 있으니 매수 시점을 늦추는 것도
> 검토해 보세요.

전세가율 약점도 자동으로 메워집니다.

> 이 리포트의 전세가율(평균 59%)은 현재 시점 추정값입니다. 위 입주 시기에는
> 전세가 눌릴 수 있어 그때의 전세가율은 지금보다 낮아질 가능성이 있습니다.

## 반드시 알아야 할 한계

**세대수가 실제보다 적게 잡힙니다.**

청약홈 `공급규모`는 일반·특별공급 세대수라 **재건축 조합원 분양분이 빠집니다.**
래미안 레벤투스가 133세대로 잡히는 게 그래서입니다.

그래서 이 집계는 실제 입주물량의 **하한**입니다. 코드와 리포트 모두
`분양 기준 최소 물량`으로 표기하고, 문장 끝에 항상 이 사실을 밝힙니다.
테스트로 강제하고 있습니다 (`test_sentence_always_discloses_the_undercount`).

물량이 확인되지 않아도 만점(100점)을 주지 않고 85점으로 처리하는 것도 같은 이유입니다.

> **"공급 없음"이라고 단정하면 안 됩니다.** 적게 잡히는 방향의 오차라서
> 물량이 안 잡혔다고 안심시키는 게 위험합니다.

**주소 파싱 실패 33건 (1.2%)** — `비수도권 소재 국민임대주택`처럼 주소가 아닌 것,
`풍산읍 막곡리`처럼 시군구가 없는 것들입니다. 추측해서 채우지 않고 버립니다.

## 데이터 갱신

청약홈 키는 `설정.txt`의 `청약홈키`에 있습니다.

```bash
cd ~/Documents/집픽
PYTHONPATH=pipeline python3 pipeline/applyhome_supply.py
```

기본값으로 **900건까지만** 받고 기존 CSV에 합칩니다. 여러 번 나눠 돌려도
데이터가 쌓이기만 하고 줄지 않습니다. 전체를 한 번에 받으려면 `--budget 0`.

**분양 공고는 계속 나오니 월 1회 정도 돌리세요.** 갱신을 안 하면 새 분양이 빠진 채
"공급 적음" 판정이 나갑니다.

### 일일 트래픽 한도 (중요)

공공데이터포털 계정 등급입니다.

| 계정 | 일일 트래픽 |
|---|---|
| **개발계정** (현재) | 1,000건 |
| 운영계정 | 10만건 |

**여기서 세는 단위는 호출 수가 아니라 레코드 수입니다.** 전국 2,833건을 한 번에
받으면 그날 한도가 끝납니다. 실제로 그렇게 됐었습니다.

한도를 넘기면 **오류가 아니라 `totalCount: 0`에 빈 배열**이 돌아옵니다.
이걸 "물량 없음"으로 처리하면 공급 경고가 통째로 사라지므로,
코드가 이 상황을 따로 감지해 중단하고 기존 CSV를 보존합니다
(`QuotaExhausted`, 테스트로 잠금).

한도를 늘리려면 **운영계정**으로 올리면 됩니다.

> 공공데이터포털 로그인 → **마이페이지** → **데이터활용 → Open API**
> → **활용신청 현황** → 해당 API → **운영계정 신청** (PC에서만 가능)

운영계정은 활용사례 등록을 요구합니다. 집픽이 실서비스라 등록할 내용은 있습니다.
다만 월 1회 갱신이면 `--budget` 기본값으로 나눠 받는 걸로 충분합니다.

> ⚠️ `설정.txt`를 `.gitignore`에 추가했습니다. API 키가 들어 있어 커밋되면 안 됩니다.
> 이전에 안내드린 `git add -A` 명령이 위험했습니다. 지금은 막혀 있습니다.

## 다음 단계

**1. 조합원 분양분 보정 — 가장 큽니다**

[국토교통 통계누리 주택건설실적통계(준공)](https://stat.molit.go.kr/portal/cate/statMetaView.do?hRsId=468)에서
지역별 준공 세대수를 받아 같은 시기 청약홈 집계와 비교해 계수를 뽑습니다.

```
보정계수 = 통계누리 준공 실적 ÷ 같은 시기 청약홈 분양 집계
추정 입주물량 = 청약홈 집계 × 보정계수
```

전국 평균 계수 하나로 시작해도 지금보다 훨씬 정확해집니다.
계수가 1.5면 평택 27,229세대가 4만 세대가 되고, 노원구는 notable → heavy로
**판정 등급 자체가 바뀝니다.**

**2. 반경 기반 집계**
