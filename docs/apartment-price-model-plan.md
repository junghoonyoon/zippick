# 집픽 가격 판단·가격 전망 모델 기획안

작성일: 2026-09-29 · 상태: 현재 적정가격 v1 구현 · 범위: 분석 리포트의 매수 판단 밴드

## 1. 만들려는 기능

**“이 가격이 지금 시세에 비해 싼지”를 먼저 답하고, “앞으로의 가격 흐름”을 따로 보여준다.**

최근 거래 평균에서 일괄적으로 5%를 더하거나 빼는 방식을 다음 세 가지 결과로 바꾼다.

| 결과 | 사용자가 보는 답 | 판단 기준 |
|---|---|---|
| 현재 가격 | 쌈 / 적정 / 비쌈 | 같은 조건의 집이 지금 거래될 것으로 추정되는 범위와 비교 |
| 향후 흐름 | 6개월 가격 전망과 예상 범위 | 지역·주변 단지·금리·전세·거래량 등을 과거 자료로 검증한 모델 |
| 근거 충분성 | 자료 충분 / 일부 부족 / 판단 보류 | 거래 수, 최근 거래일, 비교 단지, 과거 예측 오차 |

여기서 ‘적정’은 **현재 시장의 거래 수준에 비슷하다**는 뜻이다. 시장 전체가 장기적으로 저평가됐다는 뜻이나 매수 권유로 사용하지 않는다. 자금 여력은 기존 예산·대출 계산에서 별도로 판단한다.

예를 들어 ‘현재 가격은 쌈, 앞으로의 흐름은 하락 우려’가 함께 나올 수 있다. 두 결과를 하나의 점수로 합쳐 이 차이를 지우지 않는다.

## 2. 현재 집픽에서 확인한 출발점

아래는 코드를 읽어 확인한 내용이다. 실제 운영 데이터의 수집 범위와 외부 서비스의 내부 계산은 추가 확인이 필요하다.

| 현재 자산 | 확인한 내용 | 활용 방향 |
|---|---|---|
| `앱화면/real-estate-search.html` | `zippickPriceCheckBasis()`에서 최근 3개월 평균을 고르고, `zippickBuyBandTier()`에서 0.95·1·1.05배로 4개 구간을 나눔 | 서버가 내려준 3개 가격 구간과 판단 보류를 표시하도록 변경 |
| `pipeline/molit_transactions.py` | 매매·전월세, 면적·층·날짜·법정동·지번, 직거래·취소 거래 제외 로직 | 거래 정제와 단지 식별 재사용 |
| 같은 파일의 `_current_price_estimate()` | 최근 거래에 가중치를 둔 중앙값과 25~75백분위 범위가 별도로 존재 | 기존 비교 모델로 보존. 검증된 예측 구간으로 오인하지 않음 |
| `pipeline/momentum_signals.py` | 면적 구성을 맞춘 가격 변화, 거래량, 같은 구 대표 단지·대장 비교 | 원자료와 특징 계산 재사용. 기존 100점은 가격 예측 정답으로 사용하지 않음 |
| `pipeline/rone_estimates.py`, `pipeline/search_server.py` | 외부 추정 서비스 연결, 지역 R-ONE 지수 이력 추출·병합 | 출처·지역·통계 종류를 검증하고 지수 수집 기반으로 활용 |
| `pipeline/supply_forecast.py` | 분양 공고 물량과 보정계수를 적용한 입주 추정 물량을 구분 | 원본·추정치·관측 시점·수집 범위를 나눠 사용 |
| `pipeline/report_store.py` | 리포트 저장과 공유 | 당시 모델 버전·입력 자료·판단 결과를 함께 저장 |

기본 설정상 실거래 조회는 6개월, 시장 신호는 24개월이다. 이는 학습용 장기 데이터가 충분히 있다는 뜻이 아니다. 확인한 코드 범위에서 ECOS 금리 수집기는 찾지 못했다.

지역 지수 연결이 있다는 사실만으로 현재 밴드에 금리·지역 흐름이 종합 반영된다고 볼 수 없다. 현재 밴드의 경계는 여전히 평균 대비 고정 비율이다.

## 3. 첫 출시 범위

**서울의 거래 자료가 충분한 일반 아파트, 전용 59㎡·84㎡ 계열부터 시작한다.**

- 화면에서는 선택한 실제 전용면적을 유지한다. 59㎡와 84㎡ 가격을 단순 비례로 환산하지 않는다.
- 같은 면적이라도 타입이 다르다는 자료가 있으면 별도로 구분한다. 타입을 모르면 그 한계를 표시한다.
- 분양권·입주권, 재건축 사업이 진행 중인 특수 단지, 초고가·희소 주택형은 초기 자동 판정 대상에서 제외한다.
- 서울 밖과 제외 대상도 기존 실거래 정보는 보여준다. 서울 모델의 판단을 다른 시장에 그대로 적용하지 않는다.
- 첫 공개 결과는 현재 가격 판단이다. 6개월 전망은 별도 검증을 통과한 범위부터 추가한다.
- 단지별 전망의 자료가 부족하면 ‘해당 구의 6개월 전망’으로 표시한다. 지역 전망을 단지 예측값처럼 보여주지 않는다.

## 4. 종합해서 볼 데이터

| 데이터 | 실제로 넣을 값 | 역할과 주의점 |
|---|---|---|
| 같은 단지 실거래 | 가격, 계약일, 면적, 층, 거래 유형, 취소 상태 | 현재 가격의 중심 근거. 평가 대상 거래 자체는 비교 근거에서 제외 |
| 서울·자치구 가격 흐름 | 공식 아파트 매매가격지수의 1·3·6·12개월 변화 | 큰 시장의 방향과 거래 시점 차이 보정 |
| 비슷한 주변 단지 | 조건을 맞춘 거래 수준·가격 변화·거래 수 | 이 단지의 상대적 가격 수준과 흐름 확인 |
| 금리 | 한국은행 기준금리, 신규 주택담보대출 금리, 각각의 변화·과거 값 | 금융 여건 반영. 기준금리와 실제 대출금리를 구분 |
| 전세 | 같은 면적 실제 전세 보증금·변화·거래 수 | 실거주 수요와 매매 가격 간 관계 확인 |
| 입주 예정 물량 | 향후 6·12·24개월 물량, 지역 주택 수 대비 비율 | 공급 부담 반영. 분양 원본과 보정 추정치를 구분 |
| 단지·입지 | 준공연도, 세대수, 좌표, 역 거리, 확인 가능한 상품 특성 | 오래된 소형 단지와 신축 대단지를 같은 조건처럼 비교하지 않음 |
| 거래 활발함 | 최근 거래 수, 세대수 대비 거래 수, 마지막 거래 경과일 | 거래가 적은 단지의 불확실성 반영 |

서울 상승률은 거래금액의 단순 평균 변화 대신 **가격지수 변화율**을 사용한다. 한국부동산원도 평균가격은 표본 구성에 민감해 지역 가격 변동률 계산에 적절하지 않다고 안내한다. [R-ONE 통계 이용 유의사항](https://www.reb.or.kr/r-one/portal/stat/briefStatPage.do)

공식 매매 실거래 API는 지역·계약월별 거래를 제공한다. 층 정보는 제공하지만 향·수리 상태를 이 자료만으로 알 수는 없다. 현재 API 명세와 실제 응답을 대조해 필드별 보유율을 확인한다. [국토교통부 아파트 매매 실거래가 API](https://www.data.go.kr/data/15126469/openapi.do)

금리는 ECOS에서 수집한다. 신규 대출 금리와 기존 대출 잔액 기준 금리를 섞지 않는다. 통계표·항목 코드와 발표일은 수집기를 만들 때 공식 목록으로 확정한다. [한국은행 ECOS](https://ecos.bok.or.kr/api/), [한국은행 통화금융통계 안내](https://www.bok.or.kr/portal/bbs/B0000217/view.do?listType=G&menuNo=200144&nttId=10047694&pageIndex=9)

주간·월간 가격동향지수와 공동주택 실거래가격지수는 서로 다른 통계다. 동일한 시계열처럼 이어 붙이지 않는다. 지역별 제공 범위도 확인한다. [R-ONE 통계 목록과 지역 범위](https://www.reb.or.kr/r-one/portal/main/indexPage.do)

다음 자료는 첫 모델에서 제외하거나 조건부로만 쓴다.

- 매매가에 일정 비율을 곱해 만든 추정 전세가: 다시 매매가 예측에 넣으면 같은 정보를 돌려 쓰므로 제외한다.
- 뉴스·유튜브 의견·기존 집픽 종합점수: 가격 정답이나 숫자 가산점으로 쓰지 않는다. 설명용 근거로 유지한다.
- 개발 호재: 사건의 실제 발생일·당시 공개일·단계를 확보한 경우에만 후속 실험에 넣는다.
- 매물 호가: 사용자가 입력하거나 사용 권한이 확인된 자료만 평가 대상으로 쓴다. 실제 계약 가격과 분리한다.
- 향·수리·조망: 수집·검증 가능한 이력이 생기기 전에는 임의로 ‘남향 +3%’ 같은 보정을 하지 않는다.

## 5. 주변 단지는 어떻게 고를까

가까운 단지라는 이유만으로 비교하지 않는다. 다음 순서로 비교군을 구성한다.

1. 같은 생활권에서 시작한다. 초기 탐색 반경은 1~2km를 실험하되, 강·큰 도로·학군·역 접근성 등 확인 가능한 경계를 함께 본다.
2. 면적, 연식, 세대수, 입지 조건, 일반 아파트 여부를 맞춘다.
3. 최근 거래가 있고 두 비교 기간에 같은 주택형이 관측되는 단지를 우선한다.
4. 목표 단지 5~10곳은 초기 탐색값이다. 거래가 부족하면 범위를 넓힌 사실을 화면에 알린다.
5. 모델 성능으로 거리·연식 허용 범위와 단지별 가중치를 정한다. 특정 대장 한 곳이 결과를 결정하지 않게 한다.

평가하려는 가격과 비슷한 단지만 고르면 비교 결과가 그 가격을 따라간다. 따라서 대상 매물가나 평가 대상 거래가격을 비교군 선택에 사용하지 않는다. 기존 주변 단지 선택 코드의 가격 조건은 그대로 가져오지 않는다.

**“주변이 10% 오를 때 이 단지는 3% 올랐다”만으로 싸다고 판단하지 않는다.** 원래 입지·연식 차이로 가격 격차가 있었는지, 격차 확대가 거래 구성 변화 때문인지 함께 확인한다.

## 6. 모델 A: 지금의 적정 가격 범위

### 무엇을 맞히는 모델인가

입력은 단지, 면적, 층, 평가 기준일과 그때까지 공개된 자료다. 정답은 같은 조건에서 성립한 정상 매매 거래가격이다.

학습에서는 한 거래를 평가할 때 그 거래가격을 특징 계산과 비교 거래에 넣지 않는다. 출력은 하나의 정답 가격이 아니라 **중심 추정가와 거래 가능 범위**다.

층을 알면 해당 층 조건을 사용한다. 층을 모르면 관측된 층 구성에 따른 단지·면적 기준 범위를 사용하고 ‘층 미입력’을 표시한다. 숨은 집 상태까지 정확하게 평가했다고 표현하지 않는다.

### 어떤 계산부터 비교할까

| 후보 모델 | 계산 | 목적 |
|---|---|---|
| 기준 모델 0 | 현재의 최근 3개월 평균 | 지금보다 개선됐는지 비교 |
| 기준 모델 1 | 같은 조건의 최근 거래 중앙값 | 평균 대신 중앙값만 써도 나아지는지 확인 |
| 기준 모델 2 | 과거 거래가격 × 지역지수 변화, 이후 최근성·유사도 가중 중앙값 | 지역 흐름 반영만으로 얻는 개선 측정 |
| 학습 모델 | CatBoost를 이용해 단지·면적·층·지역 흐름·금리 등으로 가격과 범위를 학습 | 여러 조건을 함께 고려한 현재 거래가격 추정 |

CatBoost는 1차 구현 후보다. 분위수 예측으로 낮은 쪽·가운데·높은 쪽 가격을 학습할 수 있다. 알고리즘 선택은 시간순 검증 성능으로 확정한다. [CatBoost 분위수 회귀 문서](https://catboost.ai/docs/en/concepts/loss-functions-regression)

가격은 로그값으로 학습하는 방식을 먼저 실험한다. 단지 간 가격 규모 차이를 줄이려는 선택이며, 화면에는 원화로 돌려 보여준다.

필요하면 지수 보정 모델과 학습 모델을 결합한다. 이때 ‘서울 30%, 주변 40%, 금리 30%’처럼 가중치를 먼저 정하지 않는다. 검증에서 오차가 작았던 조합을 사용한다. 간단한 모델이 더 좋으면 간단한 모델을 채택한다.

지역지수로 보정한 가격에 서울 상승률·자치구 상승률을 다시 더하지 않는다. 공통 시장 흐름과 주변의 추가 움직임을 구분하고, 중복 반영 여부를 비교 실험으로 확인한다.

금리 자료를 더했을 때 검증 성능이 나빠지면 모델 A에서는 빼고 모델 B와 설명 자료에서 검증한다. 모든 변수를 넣는 것보다 실제로 더 정확해지는 것이 출시 조건이다.

### ‘쌈·적정·비쌈’의 경계

처음 실험할 범위는 조건부 거래가격의 10~90백분위다. 모델이 산출한 값을 별도의 과거 검증 구간에서 보정한 뒤 사용한다. 이는 평균가격의 신뢰구간이 아니라 **개별 거래가격의 예측 범위**다.

| 조건 | 표시 |
|---|---|
| 평가 가격이 보정된 하단 미만 | 쌈 |
| 평가 가격이 하단 이상·상단 이하 | 적정 |
| 평가 가격이 상단 초과 | 비쌈 |
| 자료·정확성 검증 기준 미달 | 판단 보류 |

예측 범위가 목표대로 검증되기 전에는 ‘80% 확률로 적정’이라고 표시하지 않는다. 시장이 달라지면 구간에 실제 가격이 들어오는 비율도 달라질 수 있다.

거래가 적으면 범위를 넓히되, 너무 넓어진 범위를 ‘적정’으로 덮지 않는다. `(상단 - 하단) / 중심가 > 20%`를 초기 보류 후보로 실험하고, 거래 수·최신성·비교군 적합성까지 함께 검증해 최종 기준을 정한다. 20%는 확정된 성능 기준이 아니다.

경계에 매우 가까우면 ‘적정 구간의 낮은 쪽’처럼 설명을 붙인다. 표시는 읽기 좋게 반올림하되 판정은 반올림 전 값으로 계산한다.

### 비교하는 가격의 시점

- 기본: 최근 실거래 금액을 오늘의 범위와 비교한다. 문구는 ‘9월 10일 거래가격을 오늘 기준으로 비교했어요’처럼 쓴다.
- 최신 거래가 오래됐으면 ‘현재 실거래가’라고 부르지 않는다. 현재 평가에 쓰기 부적절하면 거래 기록만 보여준다.
- 평가 대상 거래는 모델 학습·단지 평균·주변 지표 등 모든 입력 경로에서 제외한다. 단순히 비교 목록에서 숨기는 것으로 끝내지 않는다.
- 이를 위해 단지·면적별 제외 모델, 검증용 분할 모델 등 비용을 포함한 구현을 결정한다. 배치 학습 모델이 이미 대상 거래를 학습했다면 그 모델로 해당 거래를 독립 평가했다고 표시하지 않는다.
- 별도로 ‘계약 당시 가격 평가’를 제공할 때만 계약 시점 이전의 자료로 다시 계산한다. 오늘 기준 평가와 섞지 않는다.

## 7. 모델 B: 6개월 뒤의 가격 흐름

### 예측 대상

초기에는 서울·자치구의 6개월 가격지수 변화를 예측한다. 단지 전망은 거래 자료가 충분한 단지·면적부터 실험한다. 매달 거래가 없는 단지의 가격을 억지로 채워 개별 단지 예측을 만들지 않는다.

단지 모델의 정답 후보는 기준일로부터 5~7개월 뒤의 **같은 면적·층 조건을 맞춘 거래가격 수준**이다. 정확히 6개월째 거래가 없을 수 있어 기간을 명시한다. 해당 기간의 유효 거래가 부족하면 그 행에는 정답이 없는 것으로 두고 단지 학습·평가에서 제외한다.

거래가 있는 단지만 남기는 데서 생기는 편향을 확인하기 위해 ‘전체 대상 중 평가할 수 있던 단지 비율’도 보고한다. 정답이 없다고 가격 변화 0%로 채우지 않는다.

### 학습 방법

- 최근 1·3·6·12개월 지역·주변 흐름, 금리 수준·변화·시차, 거래량, 전세, 당시 알려진 입주 물량을 사용한다.
- 처음에는 단순 회귀와 트리 모델을 비교한다. 거래 수에 비해 독립적인 월별 시장 상황은 적다는 점을 고려한다.
- 현재 수준 유지와 최근 지역 추세 연장을 비교 기준으로 둔다.
- 미래의 실제 금리·미래에 발표된 정책을 과거 예측의 입력으로 사용하지 않는다.
- 금리 0.5%p 하락·유지·상승은 후속 시나리오 기능으로 분리한다. 다른 조건을 둔 가상 계산이며 인과효과나 확정 예측으로 표시하지 않는다.
- 개별 단지의 현재 가격 오차와 향후 변화 오차를 함께 반영해 미래 가격 범위를 산출한다. 두 오차를 독립이라고 가정해 단순히 더하지 않는다.

공개 결과는 중심 전망과 넓은 예상 범위다. ‘상승 가능성 72%’처럼 확률을 표시하려면 확률 검증도 별도로 통과해야 한다. 상승·보합·하락의 경계와 공개 기준 역시 검증 자료에서 정한다.

지역·금리·전세가 함께 움직였다는 사실은 원인을 입증하지 않는다. 설명은 ‘모델이 가격을 높게 추정한 요인’으로 쓰고 ‘금리 인하 때문에 반드시 오른다’고 쓰지 않는다.

## 8. 학습 데이터가 먼저 갖춰야 할 조건

초기 수집 목표는 서울의 2015년 이후 월별 거래·금리·가격지수다. 실제 제공 시작일, 이용 조건, 호출 한도, 식별 품질에 따라 기간을 확정한다. 모든 부가 자료에 10년 이력이 있다고 가정하지 않는다.

| 저장 항목 | 필요한 이유 |
|---|---|
| 단지 고유값, 지역, 법정동, 지번, 면적 | 같은 이름의 다른 단지를 섞지 않기 위해 |
| 계약일, 지표 기준월 | 어떤 시점의 사실인지 구분하기 위해 |
| 공식 발표일, 최초 관측일, 수집일, 수정 버전 | 당시 알 수 있었던 자료만 사용하기 위해 |
| 원본 값, 단위, 출처, 변환 기록 | 가격·금리·면적 단위와 보정 과정 확인을 위해 |
| 취소·정정 이력, 중복 판정 기록 | 나중에 취소된 거래와 같은 거래의 재수집을 추적하기 위해 |
| 실제 관측값 / 추정값 / 결측 | 없는 자료를 0이나 실제 자료로 취급하지 않기 위해 |

거래는 나중에 신고·정정될 수 있다. 오늘 내려받은 과거 자료만으로 과거 시점의 서비스 상태를 완벽히 재현할 수 없다. 발표 당시 버전이 없는 자료는 보수적인 이용 시차를 적용한 재구성 검증으로 표시하고, 지금부터 원본 버전을 누적한다.

현재 거래 필터를 통과한 결과만 보관하지 않는다. 원본과 제외 이유를 함께 저장한다. 낮거나 높은 가격이라는 이유만으로 정상 거래를 일괄 삭제하지 않으며, 학습용 이상값 처리와 전체 정상 거래에 대한 성능 평가를 구분한다.

공급·정비사업·정책도 당시 알려진 상태를 저장해야 한다. 현재의 입주 일정·사업 단계·대장 단지 목록을 과거 전체 기간에 소급 적용하지 않는다. 과거 이력을 복원할 수 없는 변수는 초기 과거 검증에서 제외한다.

단지 정규화는 기존 식별 기준을 유지한다. 고유값 우선, 다음은 지역·법정동·지번·단지명이며, 이름만으로 합치지 않는다. 행정구역 변경과 이름 변경도 별도 이력으로 관리한다.

## 9. 얼마나 믿을 수 있는지 검증하는 방법

**과거 자료로 학습하고 그다음 기간을 맞혀 본다. 거래를 무작위로 섞어 정확도를 계산하지 않는다.** 시간순 검증은 시계열 자료의 기본 비교 방법이다. [scikit-learn 시간순 검증 예제](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html)

1. 과거 학습 → 이후 보정·모델 선택 → 마지막 미사용 평가 기간 순으로 나눈다.
2. 기준일을 여러 번 앞으로 옮겨 상승·하락·횡보 구간에서 반복 평가한다.
3. 6개월 전망 학습에는 정답 기간이 학습 마감일 전에 끝나고 공개까지 된 행만 넣는다. 평가 기간과 겹치는 미래 정답은 제거한다.
4. 같은 단지의 과거 거래는 사용할 수 있지만, 평가 거래와 그 이후 거래는 사용할 수 없다. 처음 보는 단지에 대한 별도 평가도 한다.
5. 단지·월 단위로 묶어 오차와 결과의 불확실성을 계산한다. 같은 달 수천 건의 거래를 수천 번의 독립적인 금리 실험처럼 취급하지 않는다.

| 검증 항목 | 확인할 내용 |
|---|---|
| 가격 오차 | 원화 평균 절대오차, 비율 오차의 중앙값·상위 10% 경계 |
| 가격 범위 | 실제 정상 거래가 제시 범위 안에 들어온 비율과 범위의 폭 |
| 지역·가격대별 성능 | 자치구, 59/84㎡, 연식, 거래량, 가격대별 편차 |
| 변수의 도움 | 금리·지역·주변·전세·공급을 하나씩 빼고 넣었을 때의 차이 |
| 공개 가능 범위 | 전체 대상 중 자동 판단이 가능한 비율과 보류 이유 |
| 가격 라벨 | 경계 부근의 안정성, 후속 비교 거래가 평가와 일치하는 정도 |
| 전망 | 무변화·추세 모델 대비 오차, 방향 판단, 확률을 제공하면 확률의 일치도 |

‘쌈’이라는 라벨의 정답이 거래 데이터에 직접 들어 있지는 않다. 자기 모델이 만든 라벨을 정답으로 삼아 정확도를 주장하지 않는다. 숨겨 둔 거래의 가격 오차와 가격 범위, 이후의 독립적인 유사 거래, 표본 검토를 함께 본다. 이후 수익률은 별도의 전망·성과 분석이다.

초기 출시 심사 기준의 제안값은 다음과 같다. **아직 달성한 수치가 아니다.**

- 가장 좋은 단순 기준 모델 대비 가격 비율 오차 중앙값 10% 이상 상대 개선을 목표로 한다. 예: 6% → 5.4% 이하.
- 개선은 같은 대상 집합에서 비교한다. 어려운 단지만 보류해 얻은 개선과 구분한다.
- 목표 80% 범위는 충분한 검증 표본에서 실제 포함률 75~85%를 우선 점검한다. 표본 수와 통계적 오차도 함께 보고한다.
- 표본이 적은 구간은 ‘검증 완료’로 표시하지 않는다. 실패한 지역·주택형은 보류하거나 검증된 단순 모델로 제한한다.
- 새 지표가 모델을 더 복잡하게 만들기만 하면 제외한다. 범위를 무작정 넓혀 포함률만 높이는 것도 통과로 보지 않는다.

## 10. 사용자에게 보여줄 리포트

순서는 **판단 → 가격 범위 → 이유 → 자료의 한계 → 다음 확인**으로 고정한다. 근거 설명은 보통 세 가지 이내로 보여준다.

다음은 계산 결과가 아닌 화면 설명용 가상 예시다.

> **최근 실거래는 집픽 기준 ‘쌈’ 구간이에요.**
>
> 최근 실거래: 9억 4,000만원 · 9월 10일 · 전용 84.9㎡ · 10층  
> 집픽 추정 적정 범위: **9억 8,000만~10억 4,000만원**  
> 중심 추정가: 10억 1,000만원 · 최근 거래는 중심보다 약 6.9% 낮아요.
>
> 같은 단지 거래와 비슷한 주변 단지의 가격을 함께 봤어요.  
> 최근 지역 가격 흐름과 거래 시점 차이도 반영했어요.
>
> 자료 충분 · 사용한 거래 18건 · 비교 단지 6곳  
> 9월 10일 거래가격을 9월 29일 기준으로 비교했어요.  
> 향·수리 상태는 반영하지 못했어요. 같은 조건의 매물을 확인해 주세요.

별도 전망 영역은 다음처럼 표시할 수 있다. 이 숫자 역시 가상 예시다.

> **6개월 뒤 중심 전망은 지금보다 2% 높아요.**  
> 예상 변화 범위: -4%~+7%  
> 내려갈 가능성도 있어요. 전망 기준은 해당 구의 아파트 가격지수예요.

‘왜 이렇게 봤나요’를 펼치면 사용한 실제 거래, 비교 단지, 적용한 지수의 기준월, 금리 발표일, 미반영 항목을 보여준다. 모델 기여도는 상관된 변수 때문에 달라질 수 있으므로 검증되지 않은 ‘금리 효과 +2,300만원’을 단정적으로 표시하지 않는다.

추가 상태 문구:

- 자료 부족: ‘비슷한 조건의 거래가 적어 가격 판단을 보류했어요.’
- 범위 과다: ‘추정 가격 차이가 커서 싸거나 비싸다고 판단하기 어려워요.’
- 미수집: ‘이 지역은 아직 가격 모델 검증을 마치지 않았어요.’
- 새로 계산 중: 회전 표시와 ‘최근 거래와 주변 단지를 확인하고 있어요.’
- 오래된 결과: ‘○월 ○일 자료로 계산했어요. 최신 자료로 다시 확인해 주세요.’와 새로고침 버튼.

판단은 색만으로 구분하지 않는다. 숫자·근거 문장은 모바일에서도 줄바꿈하고, 핵심 가격·판단만 굵게 표시한다. 집 상태 등 실제 누락 항목은 상세 설명에서 다시 확인할 수 있게 한다.

## 11. 집픽 코드에 붙이는 구조

가격 계산은 서버 한 곳에서 수행한다. 프런트엔드에 다른 판정식을 두지 않는다.

| 제안 구성 | 역할 |
|---|---|
| `pipeline/valuation_data.py` | 실거래·단지 자료 정제, 원본 버전과 단지 식별 관리 |
| `pipeline/macro_indicators.py` | R-ONE·ECOS 수집, 통계별 발표일·단위·수정 버전 관리 |
| `pipeline/valuation_features.py` | 기준일 당시 이용 가능한 특징과 주변 비교군 생성 |
| `pipeline/price_valuation.py` | 현재 가격 범위, 판정, 보류 이유, 근거 생성 |
| `pipeline/price_forecast.py` | 검증된 지역·단지의 6개월 전망 |
| `scripts/train_price_models.py` | 오프라인 학습·범위 보정·모델 파일 생성 |
| `scripts/backtest_price_models.py` | 과거 시점 검증과 지역별 성능 보고서 |

초기 저장은 원본 파일·Parquet와 메타데이터 DB 정도로 시작한다. 별도 실시간 대형 학습 시스템은 필요하지 않다. 실제 데이터 규모와 운영 환경을 확인한 후 저장 기술을 확정한다.

현재 분석 API 응답에 `valuation`을 추가하고, 필요할 때만 `forecast`를 추가한다. 중요한 필드는 다음과 같다.

- `status`, `verdict`, `modelVersion`, `asOf`, `dataVersion`.
- `identity`: `apartmentId`, 지역, 법정동, 지번, 면적, 층 조건.
- `evaluatedPrice`: 최근 실거래인지 입력 매물가인지, 금액, 거래일, 제외 대상 거래 식별자.
- `fairPrice`: 중심·하단·상단, 단위, 범위 산출 방식과 검증 상태.
- `evidence`: 실제 비교 거래·단지 식별자, 사용 수, 기준 기간, 출처.
- `dataQuality`: 빠진 자료, 최신성, 보류 이유. 임의의 ‘신뢰도 92점’은 만들지 않음.
- `forecast`: 전망 대상의 지역/단지 구분, 기간, 중심·범위, 별도 버전.

가격의 내부 단위는 하나로 통일한다. 예를 들어 만원 정수로 저장하고 표시할 때 억·만원으로 변환한다. 금리 변화의 `%p`와 가격 변화의 `%`도 구분한다.

캐시에는 단지명만 쓰지 않는다. 고유값·면적·층 조건·기준일·모델/자료 버전·제외 거래를 포함한다. 입력 매물가는 추정가를 바꾸는 모델 특징으로 쓰지 않고, 이미 추정한 범위와 비교하는 데 사용한다.

리포트·검색·후보 카드·지도·종합점수표는 같은 API 결과를 사용한다. 기존 가격 점수와 새 밴드가 서로 다른 결론을 내리지 않도록 계산 계약을 정리한다. 개별 매물가를 넣지 않은 종합점수에 임의의 ‘쌈’ 점수를 가산하지 않는다.

저장된 리포트는 당시 결과와 모델 버전을 보존한다. 나중에 모델이 바뀌어도 공유 리포트가 조용히 다른 결론으로 변하지 않게 한다.

API 실패나 자료 부족 때는 `판단 보류`와 확인 가능한 실거래를 반환한다. 과거 ±5% 계산을 새 모델의 판단처럼 대신 표시하지 않는다.

## 12. 개발 순서와 완료 조건

기간은 데이터 접근과 개발 담당자가 확보됐을 때의 작업량 추정이다. 자료 정합성 문제에 따라 달라진다.

| 단계 | 예상 작업량 | 결과물과 완료 조건 |
|---|---|---|
| 1. 데이터 확인 | 약 1주 | 거래 기간·단지 식별률·결측·지수/금리 발표 이력 조사. 서울 59/84㎡ 지원 범위 확정 |
| 2. 기준 모델 | 약 1~2주 | 학습 테이블, 최근 평균·중앙값·지역지수 보정 모델, 과거 검증 보고서 |
| 3. 현재 가격 모델 | 약 1~2주 | 조건을 반영한 가격 범위, 비교군, 보류 기준. 단순 모델 대비 개선 확인 |
| 4. 리포트 연결 | 약 1주 | API·리포트·공통 카드 연결, 근거 화면, 모델 버전 저장, 회귀 확인 |
| 5. 조용한 운영 검증 | 약 2~4주 이상 관측 | 사용자에게 공개하기 전에 실제 수집·추정 로그와 신규 거래 비교. 오류·자료 지연 점검 |
| 6. 6개월 전망 실험 | 별도 약 2~4주 개발 | 지역 전망부터 과거 검증. 단지 전망은 충분한 거래가 있는 범위만 심사 |

현재 가격 모델의 개발은 대략 4~6주를 가정하지만, 공개 시점은 검증 통과 여부로 정한다. 2~4주의 운영 관측만으로 6개월 전망이 검증됐다고 주장하지 않는다. 6개월 전망의 새 예측 성과는 해당 기간과 자료 공개 지연이 지난 뒤에 확인할 수 있다.

현재 적정가격 v1은 최근 실거래 가중 가격대, 표본·최신성에 따른 최소 범위, 단지·지역·주변 단지 흐름의 제한적 시간 보정을 구현했다. ECOS 키가 있으면 기준금리와 1년 변화도 근거에 붙인다. 장기 학습 데이터로 하는 과거 성능 측정과 6개월 가격 전망은 아직 공개하지 않는다.

운영 후에는 거래를 주기적으로 갱신하고 지수·금리는 발표 일정에 맞춰 반영한다. 월별 재학습을 초기 후보로 두되, 새 모델은 기존 모델과 같은 기간에서 비교한 뒤 교체한다. 지역별 오차·범위 포함률·보류율이 나빠지면 해당 구간의 자동 판단을 중단하거나 검증된 모델로 되돌린다.

**첫 개발 단위는 ‘서울의 같은 조건 거래를 정확히 묶기 → 지역 흐름을 반영한 현재 가격 범위 → 과거 검증’이다.** 이 기반이 확인된 뒤 금리·전세·공급의 추가 효과와 6개월 전망을 차례로 붙인다.
