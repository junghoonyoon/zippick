# 생활권 변화 개선 계획

목적: 주변 계획이 무엇이고 이 단지의 생활이 얼마나 달라질지 구분한다. 결론 → 평가 범위 → 지역/단지 영향 → 근거 → 주의점 순서로 짧게 표시한다.

## 현재 구조
- 실제 리포트는 `앱화면/real-estate-search.html`의 공통 렌더러와 Python `search_server.py`의 `/api/apartment-report`를 사용한다. Next.js 지도 앱과는 별도다.
- 후보·검색·지도에서 같은 리포트 렌더러를 사용한다. 기존 종합 점수와 결제/권한 로직은 수정하지 않는다.
- 단지는 기존 apartmentId, 법정동, 지번으로 연결한다. JSON/CSV와 파일 캐시가 주 저장 방식이며 ORM/PostGIS는 없다.
- 기존 공급·철도·정비사업 자료는 지역 참고 정보다. 같은 구에 있다는 이유로 반경 1.5km 또는 직접 수혜로 간주하지 않는다.
- 기존 수정사항이 많으므로 관련 부분만 추가 수정한다. `design-md/ZIPPICK_DESIGN.md`는 없어서 REAL_ESTATE_STYLE.md를 적용한다.

## 구현
1. 버전별 설정, 공식 근거 검증, 6개 지역 항목·4개 단지 항목의 순수 계산과 공개 조건을 독립 모듈로 구현한다.
2. 수동 검증 JSON 등록을 원자적으로 저장한다. 동일 자료는 중복 저장하지 않고 과거 이력과 결과 스냅샷을 보존한다.
3. 기존 단지 ID 기반 API와 공통 리포트에 연결한다. 오류가 나도 나머지 리포트는 동작한다.
4. 제목에 판단 상태를 먼저 표시한다. 거리만으로 매기던 별점은 제거한다. 항목별 근거는 펼쳐 볼 수 있게 하고 사업 목록은 5건까지만 먼저 보인다.
5. 누락·오래됨·0점·완료 사업·등록 검증·API·모바일/데스크톱을 확인한다.

## 데이터 공백과 범위
- 공식 시작점 확인: 서울 정비사업 정보몽땅 https://cleanup.seoul.go.kr/ , 성남 개발톡톡 https://dept.seongnam.go.kr/talktalk/ , 건축HUB https://www.data.go.kr/data/15134735/openapi.do . 자동 수집이나 재배포 권한을 추정하지 않는다.
- 노후 토지 원천자료는 미확보다. 공간 연산은 선택 의존성 Shapely/PyProj로 구현한다. EPSG:5179에서 반경 교차·중복 제거를 수행하고, 의존성이나 실제 도형 자료가 없으면 면적 점수를 계산하지 않는다.
- 공식 연속지적도 수집 경로를 추가했다. 브이월드 별도 키가 있으면 1.5km 원을 1km 격자로 나눠 모든 페이지를 검증하고 필지 경계를 별도 SQLite에 저장한다. 건물 속성·사업 경계와 연결되기 전에는 점수로 쓰지 않는다.
- 교통 경로·보행 연결·시설 개선·수요 공급 기준을 확인하지 못한 항목은 null이다. 실제 단지에 테스트 값을 넣지 않는다.
- 점수 공개는 환경변수로 기본 OFF. 개선된 현황 UI는 항상 제공하고, 검증된 데이터와 플래그가 함께 있을 때만 수치가 나온다.
- 운영 배포, 정기 배치 자동화, 관리자 화면, 시세 예측은 이번 요청에 포함하지 않는다.
