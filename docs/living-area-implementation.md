# 단지별 생활권 변화 적용 결과

**구 전체 개발사업 별점을 단지별 근거 분석으로 교체했다.**
실제 자료가 부족하면 `평가 보류`로 표시한다. 가상 수치·가격 상승률은 제공하지 않는다.

## 구조와 데이터 흐름

실제 서비스는 `앱화면/real-estate-search.html`과 Python `search_server.py`를 사용한다.
Next.js 별도 화면도 있지만 리포트의 주 경로가 아니다. 웹 PDF는 html2pdf로 같은 DOM을
복제하고, 일반 인쇄는 CSS로 처리한다. 지도는 카카오 SDK와 Leaflet/OpenStreetMap 대체 경로, 분석 이력 저장은 로컬 SQLite다.
이 기능에 Supabase/Postgres 마이그레이션은 필요하지 않다.

공식 파일 → 원본 스냅샷 → 허용 출처 검사 → 정규화 → 중복 검토 → 단지 ID/주소 대조 →
확인된 대표점 거리·보행 연결 → 결정론적 점수 → 공통 분석 JSON → 웹/PDF 순서다.

쓴다. 지역 점수를 총점이나 매수 추천 점수에 추가하지 않았다. 기존 미커밋 작업은 유지했다.

## 계산 정책

- 지역: 노후주거지 전환 30%, 주거벨트 15%, 교통 15%, 생활시설 15%, 실현 가능성 15%, 공급·수요 10%.
- 직접 수혜: 접근성 30%, 노출도 25%, 실행 가능성 20%, 상대 경쟁력 15%, 부정 영향 역점수 10%.
- 종합: `(지역 × 0.6 + 직접 수혜 × 0.4) / 20`, 소수 한 자리 반올림.
- 필수 항목이 하나라도 없으면 종합 `insufficient_data`, 점수 `null`. 남은 항목으로 가중치를 재분배하지 않는다.
- 거리 감쇠: 0m=1, 800m=0.6, 2km=0.2, 5km=0, 구간별 선형. 이는 검증 전 정책값이다.
- 진행 계수: 계획 .1, 구역 지정 .2, 조합 .35, 사업시행 .55, 관리처분 .7, 공사 .9.
  완료·취소·알 수 없는 단계는 앞으로의 사업 점수에서 제외한다.
- 2km 초과는 검증된 광역 연결이 있을 때만 후보로 삼는다. 예정역 출입구가 없으면 역 거리도 계산하지 않는다.
- 직접 수혜는 근거리·보행 연결·단절 검토·영향 근거를 함께 요구한다. 직선거리만 있으면 조건부다.
- 사업 수를 합산하지 않는다. 단계는 중복 제거 후 거리 가중 평균, 접근성은 검증된 보행 경로 중 최선값이다.
- 세부 점수는 지역 변화 중 주거 관련 항목, 교통 항목, 경쟁력·부정 영향·공급 수요 항목의 묶음이다.
- 모든 점수는 베타다. 정규화 기준은 코드에 명시하며 가격 예측 모델로 쓰지 않는다.

## 저장·실행

새 필수 환경변수는 없다. 서울시 기본 번들로 네트워크 없이 참고 사업을 제공한다.
새 데이터베이스 `pipeline/cache/living_area.sqlite3`는 첫 등록 때 자동 생성한다.
테이블은 `source_snapshots`, `current_sources`, `complex_observations`다.
기존 `future_transformation.sqlite3` 스냅샷에는 새 분석 JSON도 저장된다.

```sh
PYTHONPATH=pipeline .venv/bin/python pipeline/import_living_area.py seoul-plan-renewal --fetch --as-of 2026-10-13
PYTHONPATH=pipeline .venv/bin/python pipeline/import_living_area.py molit-renewal /path/to/official.csv --as-of 2026-05-18
PYTHONPATH=pipeline .venv/bin/python pipeline/import_living_area.py observations /path/to/reviewed.json
```

기준일은 파일 공식 기준일을 확인하고 입력한다. 전체 파일만 등록한다. 부분 수집은 운영 자료로
승격하지 않는다. 원본은 보존하고 최신 포인터만 원자적으로 교체한다. 완전한 파일이어서 삭제된
사업을 이전 목록에서 계속 끌어오지 않는다. 자동 스케줄은 생성하지 않았다.

단지 측정 자료에는 `modelVersion`, `apartmentId`, `identity`(district/legalDong/jibun),
`center`, `projectLocations`, `projectRoutes`, `evidence`, `measurements`가 필요하다.
각 근거의 sourceId/sourceRecordId/snapshotId/raw/asOfDate/collectedAt를 보관하고 등록 시
저장된 공식 원본과 대조한다. 외부 AI가 만든 점수는 받지 않는다. 문장은 결정론적 템플릿이다.

## 공식 자료 연결과 화면 보강 — 2026-10-15

수정 계획은 (1) 공식 출처의 이용조건 확인, (2) 최신 사업 단계·규모 보강, (3) 고유값과 주소로
좌표 연결, (4) 사실·영향·확인할 점 중심 화면, (5) API와 모바일 지도 검증 순서로 진행했다.

추가 파일은 `pipeline/living_area_context.py`, `data/living_area_apartment_points.json`,
`data/living_area_official_context.json`이다. 공통 `analyze()`에서 허용 출처·유효기간·해시를
검사하고 기존 점수 계산 결과와 별도로 `displayProjects`, `insights`, `categoryFacts`,
`coverage`를 생성한다. 새 확인 현황을 숫자 점수로 오인하지 않도록 상태 문구로 표시한다.

- 장안1구역: 2026-06-11 지정, 1,754세대, 공원 2곳, 폭 8m 공공보행통로를 실제 고시에서 확인.
- 장안현대: 746세대 계획, 2026-06-18 관리처분계획인가, 단지 대표점 간 직선거리 705m.
- 면목선: 공식 기본계획안 공청회 공고, 청량리~신내 9.36km와 정거장 10곳.
- 첫 화면에 핵심 요약·지도·주거/교통/경쟁 확인 상태를 표시하고, 사업별 진행선과 상세 근거를 연결.
- 지도는 검증된 대표점만 표시한다. 장안현대 마커를 누르면 해당 사업 근거가 열린다.
- 원문 ID, 공식 링크, 발표일, 단계 기준일, 확인일과 이용조건 검증일을 구분한다.

서울시 공식 단지 좌표 2,894행을 보관하며, 동일 코드+지역+동 또는 완전한 이름+지역+동+지번
일치로 자동 연결한다. 불완전한 주소는 검토한 바인딩만 허용한다. 이름만 일치하면 연결하지 않는다.
아래 명령은 공식 전체 건수 대조 후 좌표 파일을 원자적으로 갱신하고 검토한 바인딩을 유지한다.

```sh
PYTHONPATH=pipeline .venv/bin/python pipeline/import_living_area.py seoul-apartment-points --fetch
```

## 현재 확인된 한계

시안의 3.6점, 장안1구역 51m, 예정역 800m·도보 10분은 검증된 자료가 아니므로 사용하지 않는다.
실제 동대문더퍼스트데시앙은 공식 사업 정보를 제공하지만 11개 점수 항목 중 실현 가능성만
계산 가능하다. 보행 연결·노후주거지 토지 면적·시설 개방 시점·공급 수요 등의 입력이 없어
종합점수는 `null`이다. 서울·구 평균도 계산 근거가 없어 표시하지 않는다.

장안1구역 경계·면목선 출입구는 확인 전이다. 전체 서울 데이터는 참고 사업을 제공하지만,
최신 개별 고시 보강은 현재 장안1구역·면목선에 한한다. 국토부 API 자동 호출과 주택인허가
수집 연결은 아직 미활성이다. 자료 범위와 이용조건은 `docs/data-licenses.md`에 기록했다.

## 신설역과 계획 노선 지도 연결 — 2026-10-18

독산주공14단지 주변 지도는 신안산선 계획선과 신독산역·시흥사거리역 예정역을 함께 보여준다.
역 이름은 서울시와 국가철도공단의 자료로 확인하고, 지도 대표점은 카카오 Local 장소
`155510731`·`454414763`을 사용한다. 각 점은 경기부동산포털의 신안산선 계획선과
각각 약 353m·375m 떨어져 있다. 지도에 그린 짧은 청록 점선은 서로 다른 지도 자료를
읽기 쉽게 잇는 참고선이다. 실제 선로, 역 출입구, 도보 경로나 개통일을 뜻하지 않는다.
역 대표점에서 단지까지의 직선거리는 점수 계산에 넣지 않는다.

원본 역 좌표와 출처는 `data/living_area_rail_station_references.json`에 보관한다.
API는 같은 이름의 계획 노선이 3km 안에 있고 역 대표점이 그 노선에서 500m 안에
있을 때만 연결을 돌려준다. 출처 확인일이 120일을 넘으면 예정역 표시를 멈춘다.
기존 지도 레이어의 유료 리포트 이용권한은 `docs/data-licenses.md` 확인 사항을 따른다.
- 실제 동대문더퍼스트데시앙 60㎡ 리포트에서 장안동 587 식별과 같은 동 참고 사업 2개를 확인했다.
  거리·점수는 자료 부족으로 보류했고, 단계 기준일·수집일·출처는 구분해 표시했다.
- 데스크톱과 390px 모바일에서 생활권 표시, 가로 넘침 없음, 지도 드래그·확대·축소,
  대상 단지 선택·큰 지도 열기·리포트 복귀를 확인했다. 새 사업 마커는 검증된 좌표가 없어
  실제 데이터로 클릭 검증하지 못했다. 모바일 바텀시트 드래그의 전체 회귀 검사는 수행하지 않았다.
- 실제 PDF를 다운로드해 페이지 이미지로 확인했다. 생활권 섹션은 새 페이지에서 시작하며,
  점수 카드·계산 근거·판단이 잘리지 않는다. 웹 복제본과 같은 분석 정보를 사용하고 지도는 제외한다.

변경은 로컬 프로젝트에 적용했다. 커밋·원격 푸시·운영 배포는 수행하지 않았다.

## 세 항목과 생활권 별점 연결 (2026-10-15)

사용자 요청에 따라 확인된 사업 계획으로 비교할 수 있는 `living-area-plan-v1-beta`를 추가했다. 완전한 보행·환경·수요 실측을 요구하는 기존 v2의 score/subScores는 그대로 보존한다. v2가 미완성일 때 웹·PDF는 별도 `planRating`의 점수와 근거를 함께 표시한다. ‘공식 자료 안내’ 대체 문구는 삭제했다.

- 주거환경 = 5 × (거리계수 40% + min(계획세대/1,500, 1) 30% + 단계계수 30%). 2km 이내 사업 중 최고 1개만 사용, 중복 사업은 ID로 제거한다.
- 교통 = 5 × (계획 경유지 거리계수 60% + 추진 단계계수 40%). 사업 ID로 연결된 참고 위치만 사용하고 가장 높은 계획 1개만 반영한다. 출입구 거리·도보시간·실제 이동시간 단축으로 해석하지 않는다.
- 신축 대비 경쟁력 = 5 × (max(0,1-연식/30) 40% + min(현재세대/1,000,1) 20% + 공급계수 40%). 공급계수는 `1/(1+Σ(계획세대×거리계수×단계계수)/현재세대)`. 가중 계획세대는 실제 입주량이 아니다. 브랜드·내부 품질·실제 수요는 제외한 제한적인 비교다.

- 종합 별점: 세 항목이 모두 있을 때만 40/30/30으로 합산한다. 미확인 항목은 0점으로 간주하지 않는다.

지도는 카카오를 유지한다. 파란 참고 경계, 주황 사업명·단계 라벨, 직선거리, 실제 철도 참고 선형을 표시한다. 폴리곤은 터치를 가로채지 않으며 라벨 겹침을 줄이고 실제 사업을 넓은 참고 구역보다 우선한다. 화면 밖·겹친 라벨은 아래 출처 목록에서 선택할 수 있다. 서울 OA-22712는 사용자가 요청한 **비상업용** 조건으로 메인 지도와 리포트에 제공하며, 상업적 이용 허용으로 표시하지 않는다.

남은 범위: 모든 서울·경기 단지가 같은 조회 절차를 거치지만, 모든 단지에 새 사업·세 항목 점수가 존재한다는 뜻은 아니다. 공식 사업 목록 자체가 전수조사가 아니며 경기 경계의 상당수는 사업명/단계가 없다. 확인되지 않은 신규역 위치·보행 연결·공급 물량은 계속 미확인으로 남긴다. VWorld는 현재 설정된 인증키에 오류를 반환해 이번 경계 수집에는 사용하지 않았다. 실제로 조회되는 경기부동산포털 공개 GIS로 대체했다.

검증: 관련 자동 테스트 113개 및 실제 HTTP API 테스트 1개 통과(추가 하위 검사 11개). 프런트엔드 마지막 수정 후 지도 관련 5개 재확인, JavaScript 구문 검사와 diff 공백 검사 통과. 홍제·성남·수원·하남·고양·강남 실제 단지의 API 응답을 확인했다. 데스크톱 및 390px 모바일에서 카카오 지도 드래그·확대·구역 선택·확대 지도 열기/닫기를 확인했다. 확대/화면 크기 변경 때 지도 중심 유지, 라벨 겹침과 잘림 방지, 선택한 사업 설명 펼치기를 보완했다. 자료·경계·점수 정책 변경은 검색 후보 캐시를 무효화한다.

### 교통 자료 표시 누락 수정

노선 도형은 지도 API에 있었지만, 역 위치와 연결되지 않으면 본문 `displayProjects`에서 빠져 교통 카드와 핵심 요약에 노선명이 보이지 않았다. `transportRoutes`로 출처·원문 현황·노선 직선거리를 별도로 전달하고 점수와 무관하게 ‘확인된 교통 자료’를 펼쳐 보여준다. 노선만 확인된 경우도 핵심 요약에 포함한다. 이미 개통된 구간의 원문 표기를 보존하며 신규 역세권 수혜로 계산하지 않는다. 점수 보류 이유는 ‘교통계획이 없음’이 아니라 ‘현재 연결한 자료에 신규·변경 역 위치가 없음’으로 설명한다.

홍제 센트럴 IPARK의 GTX-A 노선 자료(직선 2,021m, 역까지 거리 아님) 본문 노출과 점수 미산출 분리를 실제 API·화면에서 확인했다. 관련 테스트 68개 통과. 데스크톱 및 모바일 390px에서 교통 자료 카드·출처 링크를 확인했다. 신규 역 위치 자료가 22곳인 수집 범위 자체를 확장한 변경은 아니므로, 교통 데이터 전수 연결 완료로 해석하지 않는다.


### 홍제 교통 점수·별점 누락 수정 (2026-10-16)

교통 자료 설명만 노출하던 상태에서, 누락된 **강북횡단선**을 공통 철도 수집 목록에 연결했다. 서울시 2026-06-09 홍제 경유 안내와 서울시의회 2026-06-15 제3차 도시철도망 구축계획안 검토보고서를 대조했다. 2024년 예비타당성조사 미통과 후 재추진하는 계획이며, 역 수 19→17 및 선형 변경 검토가 있어 확정·착공으로 표현하지 않는다.

- 목동·홍제·길음·청량리의 실제 기존 역 대표점 4개를 카카오 지하철역 검색으로 검증했다. 기존 22곳을 포함해 26곳이다. 임의 예정역 좌표·노선 선형·출입구·보행 시간은 만들지 않았다.

- 홍제 센트럴 IPARK: 기존 홍제역 대표점까지 직선 491m. 기존 거리 60%·단계 40% 식으로 **교통 2.5/5**, 주거 3.2·경쟁력 3.6을 합산한 **생활권 별점 3.1/5**. 실제 이동시간 개선 점수와 가격 상승 예측으로 전환하지 않는다.

### 서울·경기 전체 교통계획 연결 검수 (2026-10-16)

검색 등록 항목 16,731개를 대조했다. 이 가운데 352개는 여러 단지를 묶은 검색 결과이며 개별 단지로 취급하지 않았다. **개별 단지 16,379곳 전체**의 고유 ID·시도·시군구·법정동·지번을 대조했다. 카카오 주소 API의 동일 지번 결과만 보관하며, 위치 불일치나 조회 실패를 점수 0으로 처리하지 않는다.

원인과 수정:

- 화성시 지번 검색 응답에 새 구 이름이 붙어 시 단위 식별자가 불일치하던 문제를 수정했다. 시 이름만 지정된 경우 해당 시의 하위 구를 허용하되, 구가 명시된 다른 지역이나 동·지번이 다른 결과는 계속 제외한다. 재검증으로 360개 주소의 위치를 추가 확인했다.
- 확인된 위치를 ID와 전체 주소에 묶어 재사용한다. 미래·120일 초과 자료는 쓰지 않는다. 계획 자료 변경 시 메모리·후보 캐시도 갱신한다. 자료 갱신 뒤 같은 점수 누락이 반복되지 않도록 전체 검수 도구를 추가했다.
